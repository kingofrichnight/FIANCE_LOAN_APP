# Lendwise

A static, device-local loan portfolio app published through GitHub Pages. The interface uses a pen-and-paper notebook theme, with a responsive phone layout, subtle button/dialog feedback and reduced-motion support. All fonts and decorative artwork use local fonts or CSS; there are no third-party font requests.

## Using the app

- Create a **local profile** with a name and a password/passphrase of at least 12 characters. Unlock it whenever you reopen the app. There is one profile per browser/site, not an online account or a shared user directory. No email address is required.
- Choose a portfolio currency to view that currency’s borrowers and totals. Each loan stores its own currency; amounts are never converted using assumed exchange rates.
- Use **Add borrower** to save contact information, loan terms and optional PDF/image documents.
- Choose **Calculate from interest rate** or **Custom monthly payment**. Custom mode uses your entered amount for every month, including the final month, without applying an interest rate. The form shows the scheduled total and whether it is above or below the original loan amount.
- Each borrower has **Payments**, **Edit** and **Delete** controls. Deletion requires confirmation. The most recent deletion can be undone in Settings until the page is reloaded.
- **Payments** shows the full monthly schedule. Record or edit the total received for each installment and its latest received date. Partial and overdue payments are supported. Set the received amount to zero to clear the record, with confirmation.
- **Export report** downloads all borrowers and all installments, including contact details, terms, currency, amounts due/received/remaining, dates, status and days late. CSV carries status text; the native `.xlsx` export colors overdue and paid-late rows red. Export status is a snapshot at the report date.
- **Settings & backup** downloads an encrypted JSON backup including documents and payment records. Restore it with its original password on the login screen of another device to transfer the whole profile. Restoring from inside an unlocked profile replaces only that profile’s portfolio and keeps its name/password. Earlier unencrypted version 3 JSON backups can be imported from inside an unlocked profile.
- **Sign out & lock** clears displayed data and the active in-memory session. The app also locks after five minutes without activity and on page reload/navigation. Unsaved edits are discarded when it locks. **Change password** is in Settings; older backups still need their original password.
- Closing a changed borrower or payment form asks before discarding unsaved edits. Dashboard shortcuts filter active/overdue loans, borrower progress bars show the share of scheduled repayments received, and the Payments view filters paid, unpaid/partial or overdue installments.
- **Settings & backup → Make it yours** can disable decorative motion. The device’s reduced-motion setting always takes precedence.
- **How your data is stored** explains local storage, exports and security limitations. In Settings, **Remove old migration copies** removes retained migration history without changing the current portfolio. **Delete local profile** requires the password and a separate permanent-deletion confirmation; it removes this app’s profile, old migration data and preferences from this browser, not other projects’ storage. Downloaded backups and other devices are unaffected. Neither operation happens automatically when the app updates.

## Calculation and storage details

Interest-based schedules use monthly reducing-balance amortization, rounded to two decimal places, with a final installment adjustment. Custom plans use the exact entered two-decimal monthly amount for the chosen number of months; there is no automatic principal cap, interest allocation or final adjustment. Custom totals may be smaller or larger than the original amount; verify the agreed repayment terms. Their rate, principal/interest splits and principal balance are blank in exports instead of guessed. Monthly dates retain the original day where possible (January 31 becomes February’s last day, then March 31). No late fees are added automatically. An unpaid installment becomes overdue the day after its due date in the device’s local time.

The app keeps **one received total and one latest received date per installment**, not a transaction ledger. Collection totals group these records by their recorded date. If you need individual receipts across multiple dates for the same installment, export your records and use a transaction ledger.

Data stays in this browser’s local storage and is not synced or backed up to a server. Documents are limited to 1 MB each and 10 per borrower, subject to browser storage capacity (encryption and embedded files add overhead). Failed saves show an error and keep the form open. Export backups regularly. Private/incognito sessions, clearing site data, browser removal, storage eviction or device loss can lose local data. Moving from a website to an Android app does not automatically transfer its data.

Older `lendwisePortfolioV3` and `lendwiseBorrowers` data is migrated only when a profile is created. The current portfolio and exact old raw values are encrypted together; the new envelope is decrypted and validated before it is saved. Only after a successful save are unchanged old plaintext keys removed. A failed migration leaves originals untouched. Recovery copies remain inside the encrypted payload until explicitly removed in Settings, so they can include previously deleted older records and increase storage usage. Closing older app tabs before migrating prevents old versions from writing plaintext again. Earlier loans with no rate keep their saved installments as custom monthly plans. Their numeric amounts are retained with USD as the legacy denomination; verify currency and dates in Edit. Malformed records, impossible terms, sub-cent amounts and future-dated received payments are rejected instead of silently corrected. Keep an original backup if an older record requires manual correction.

## Security boundaries

- The `lendwiseVaultV1` local-storage record contains an AES-256-GCM authenticated-encryption envelope. A fresh 16-byte salt and PBKDF2-HMAC-SHA256 with 600,000 iterations derive a non-extractable key from the password; each save uses a fresh 12-byte random IV. Passwords and keys are not written to storage. The profile name, contacts, loan data, payments, documents and migration recovery copies are encrypted. Currency, reminder and animation preferences are stored separately without encryption.
- A strong, unique passphrase matters: an attacker with the encrypted file can try passwords offline. There is no email reset, server-held recovery key or automatic backup. Without the password the encrypted data cannot be recovered by this app.
- This is a device-local encrypted vault, **not server-side authentication**. The website and source code can remain public. Someone opening the link in a different browser gets a separate empty profile; they do not receive another browser’s portfolio. Public hosting still receives ordinary requests for site assets and associated connection metadata.
- Encryption protects persisted records while locked. It does not protect an unlocked session against malicious same-origin scripts, a compromised hosting account, browser extensions or device compromise. GitHub Pages project paths on the same `username.github.io` hostname share an origin; a path is not an isolation boundary. A dedicated origin or a separately packaged Android app should be assessed before production use with sensitive financial records.
- A restrictive meta Content Security Policy blocks network connections and third-party scripts. This reduces attack surface but is not a complete security audit or a substitute for a trusted device/hosting environment. GitHub Pages cannot supply all per-site security headers through this repository alone.
- CSV, Excel and downloaded documents are **not encrypted**. Previously exported plaintext backups and browser/system backups may retain old data; removing local-storage keys is not a guarantee of forensic erasure.
- Browser Web Locks and ciphertext snapshot checks prevent concurrent tabs from silently overwriting a profile. Other unlocked tabs lock when the saved vault changes. HTTPS (or localhost for tests), Web Crypto and Web Locks are required; unsupported environments fail closed.

The encryption APIs follow [Web Crypto authenticated encryption](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt) and the PBKDF2 work factor follows [OWASP guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). This implementation has automated tests but has not had an independent security audit.

## Development and verification

Serve the repository with any local HTTP server. There is no build step or application backend. The locally vendored ExcelJS 4.4.0 browser bundle is loaded only when exporting Excel; its MIT license is included.

Run calculation, encryption and workbook regression tests with `npm test` (Node.js 22+). They cover custom dues, 192 amortization scenarios, rounding, month boundaries, statuses, older records, malformed imports, validation, CSV escaping, XLSX types/styles, encryption roundtrips, random salts/IVs, wrong passwords and tampered ciphertext.

The interaction suite uses Playwright (`npm install --no-save playwright`, then `npx playwright install chromium`). Run `npm run test:ui`; set `BROWSER_CHANNEL=msedge` to use installed Microsoft Edge. The suite starts its own local server and uses only synthetic data in an isolated browser. QA downloads and screenshots go to a sibling `qa` directory, outside this repository. It covers all visible navigation and control families, custom payments, CRUD, payment editing and filters, unsaved-change prompts, documents, exports, encrypted backups, layouts from 320px to 1440px, reduced motion, invalid data and quota failures. Account coverage includes wrong passwords, sign-out/reload, changing passwords, transfer to a fresh browser, failed/successful plaintext migration, recovery-copy removal, password-confirmed profile deletion while preserving unrelated storage, multi-tab locking, timed locking, and absence of off-origin HTTP requests during the tested flows. These tests are not an independent security audit, a guarantee of correctness or a substitute for physical Android/iOS testing.
